Understand the response

A LangChain call returns an AI message object. Its text is what we usually show a user, but it is not the only useful part.

response = groq_model.invoke("Explain what an API key is in one sentence.")

print(response.text)
# Optional fields may differ by provider, so read them defensively.
print(response.response_metadata.get("model_name"))
print(response.usage_metadata)

Metadata can reveal which model actually responded. Usage metadata can report input, output, and total tokens. Providers do not all report exactly the same fields, so use .get(...) or a fallback for optional data. See the complete example in 3-Responses-and-Prompts.ipynb.

Tokens: what are they?

Before a model can work with text, it breaks that text into tokens: small pieces that can be a word, part of a word, punctuation, a space, or a line break. This Python string:

I love building AI apps!

might be seen more like:

“I”“ love”“ building”“ AI”“ apps”“!”

This is only an illustration; exact splits change by model. A word is not always one token. Long words may become several tokens, and a space often belongs to the token after it.

Why tokens instead of words or strings?

Models need a fixed set of pieces they can turn into numbers and work with consistently. Whole strings have endlessly many possible sentences, names, URLs, spelling mistakes, and made-up words. Whole words would require the model to know every word in every language. Tokens are the middle ground: small enough to split new words and large enough to avoid processing every character alone.

CONTEXT BUDGET

Why should an application developer care?

Every request has two sides.

More tokens usually mean more time and more pressure on the model’s context limit. You do not need to count every token by hand. You do need to notice when a prompt, conversation history, or retrieved document gets large. Usage is one of the first signals that an application needs better context management.

What does the model name mean?

Consider this setup:

groq_model = init_chat_model(
    "openai/gpt-oss-120b",
    model_provider="groq",
)
Three names, three jobs
NameMeaning
groq_modelOur Python variable name; it tells a reader that this object talks to Groq.
model_provider="groq"The LangChain integration that sends the request. Groq hosts the API endpoint.
"openai/gpt-oss-120b"The exact model identifier requested from Groq, distinguishing it from other models it may offer.

The provider is the restaurant serving the request; the model identifier is the particular item selected. Provider, model family, and variant affect what an application can do.

What does 120b mean?

The b means billion. In gpt-oss-120b, it is a rounded label for roughly 120 billion parameters: learned numbers adjusted during training to capture patterns. It distinguishes the model from smaller variants such as gpt-oss-20b. More parameters can mean more capacity, but do not automatically predict a better answer for every task.

This model uses a mixture-of-experts design, so not all parameters are used for every generated token. When called through Groq, the laptop does not download or load those parameters; Groq hosts the model and performs the computation. Record the model name from response metadata while testing: a specific prompt, model, and provider is evidence you can investigate.

What is a prompt?

A prompt is everything supplied to guide a response: instructions, a question, examples, formatting requirements, and context. In chat, it can be spread across system, user, and previous assistant messages.

STATIC

Fixed instruction

static_prompt = "Explain RAG in one sentence."

DYNAMIC

Runtime values

question = "What is the difference between an LLM and a chat model?"
dynamic_prompt = f"Answer this question for a beginner developer: {question}"

Dynamic prompts personalise an answer, insert a user question, or supply retrieved information. They can also become a fragile collection of string-building code.

Use a prompt template

A normal string or f-string is often best for a one-off prompt. PromptTemplate helps when the same prompt appears in several places or needs a clearer contract for its values.

from langchain_core.prompts import PromptTemplate

explanation_template = PromptTemplate.from_template(
    "Explain {topic} to a {audience} in no more than {sentence_count} sentences."
)

formatted_prompt = explanation_template.invoke({
    "topic": "tokens",
    "audience": "beginner Python developer",
    "sentence_count": 2,
})

The template gives validation and reuse. If audience or sentence_count is missing, it raises an error before a model call. A template can also live outside a Python file, making it easier to review, test, and change.

from pathlib import Path
from langchain_core.load import dumps, loads

template_path = Path("prompts/explanation_template.json")
template_path.parent.mkdir(exist_ok=True)
template_path.write_text(dumps(explanation_template, pretty=True), encoding="utf-8")

loaded_template = loads(
    template_path.read_text(encoding="utf-8"),
    valid_namespaces=["langchain_core"],
)

TECHNICAL EXPLANATION

A useful common starting point.

Direct provider calls reveal what happens at the boundary. Applications also change: providers, models, and calling styles rarely stay fixed. LangChain provides a cleaner place to begin that movement without hiding the choices behind it.

So, what is LangChain?

LangChain is a convenient set of tools for connecting to LLMs and building applications around them. Its provider-agnostic interface lets similar application code work with different model providers. It does not mean providers share every model, parameter, tool, or response field; it gives a common starting point for what they do share.

Connect with a model using LangChain

In 2-Using-LangChain.ipynb, the important line is init_chat_model.

Create the model, name its provider integration, and invoke it.

from langchain.chat_models import init_chat_model

groq_model = init_chat_model(
    "openai/gpt-oss-120b",
    model_provider="groq",
)

groq_response = groq_model.invoke(
    "How many permutations are there for a deck of 52 cards?"
)
print(groq_response.text)

# The returned AI message can also carry metadata and token usage.
print(groq_response.response_metadata.get("model_name"))
print(groq_response.usage_metadata)

The result is an AI message object, not only a string. A direct provider SDK remains useful for provider-specific features. LangChain helps when the common interface makes the application easier to write and maintain.

Invoke different models

Changing a model is simpler where the model is created. The calling pattern stays familiar, but the choice is still engineering: quality, speed, price, safety settings, context, and supported features can differ. Use the shared interface to experiment; use evaluation to decide what belongs in an application.

groq_model = init_chat_model(
    "openai/gpt-oss-120b", model_provider="groq"
)
gemini_model = init_chat_model(
    "gemini-3.1-flash-lite-preview", model_provider="google_genai"
)

print(groq_model.invoke("Explain RAG in one sentence.").text)
print(gemini_model.invoke("Explain RAG in one sentence.").text)

GENERATION CONTROL

Temperature: how much variation should we allow?

Temperature controls the randomness of a language model’s output. Lower values favour the most probable next tokens; higher values explore less likely choices more often. It is not a truth dial and cannot fix a weak prompt or missing context.

Sensible starting temperatures
TaskStarting temperatureWhy
Factual answers, maths, code, extraction0.0–0.3Favour consistency and predictable formatting.
General questions and explanations0.5–0.7Balance clarity with natural variation.
Creative writing, stories, jokes0.9–1.2Allow diverse phrasing and ideas.
Wild brainstorming1.5+Encourage surprising directions; expect less consistency.
model = init_chat_model(
    "openai/gpt-oss-120b",
    model_provider="groq",
    temperature=0.2,  # Start low when reliable structure matters.
)

Start with the task, not a fashionable number. Raise temperature for several different campaign ideas and review the results.

Max tokens: how much may the model say?

Models generate output in tokens. max_tokens, or a provider-specific equivalent, limits how much output one response may produce.

Cost

More generated tokens usually cost more.

Speed

Longer answers generally take longer to generate.

Control

A clear limit stops a short task from becoming an essay.

Choose a limit that fits the result. A classification label needs little output; a detailed report or code explanation needs more. If a response is cut off, raise the limit or ask for a smaller, more focused answer. Parameter names and accepted ranges vary by provider, so check the integration documentation for the model you use.

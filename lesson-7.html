TECHNICAL LESSON

An agent manages a familiar loop.

Lesson 6 made the execution loop visible. Agent frameworks save you from writing that standard loop for every application, while you stay responsible for tool definitions, access, permissions, error handling, and what users may ask it to do.

01 · THE PARTS

Model + instructions + allowed tools = agent.

The model reads the user request and decides whether a tool can help. The framework runs an approved tool, adds its result to the conversation, and asks the model for a final answer. An agent is not a magical employee: it can only use the tools you provide.

02 · ONE TOOL

Create an inventory agent.

The local inventory service below could stand in for a database or approved service in a real project.

@tool
def check_stock_service(item: str) -> str:
    """Return the remaining stock quantity for an inventory item."""
    stock_by_item = {"headphone": 6, "keyboard": 11, "laptop": 12}
    quantity = stock_by_item.get(item.lower())
    if quantity is None:
        return f"{item} is not present in the stock database."
    return f"{item} has {quantity} units left in stock."

basic_inventory_agent = create_agent(
    model=inventory_model,
    tools=[check_stock_service],
)

When someone asks, “How many laptops do we have?”, the agent can decide that check_stock_service is relevant. The framework handles the request, function call, tool result, and final response.

03 · MULTIPLE TOOLS

Give the agent a bounded choice.

shopping_agent = create_agent(
    model=inventory_model,
    tools=[check_stock_service, get_price_service],
)

A question such as “Do we have laptops in stock, and what is the price?” can require two tools. The model chooses which supplied tool to call and in what order. It cannot call a tool absent from the approved list.

Inspecting messages during a run reveals the user request, AI tool calls, tool results, and final response. It is a useful learning and debugging aid, rather than treating the agent as a black box.

AGENT VERSUS TOOL LOOP

The underlying sequence stays the same.

You still control the important boundary: tool definitions, data access, permissions, error handling, and the actions a user is allowed to request.

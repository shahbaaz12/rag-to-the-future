TECHNICAL EXPLANATION

One request, one response.

Your first application can be deliberately small: send a message, wait for a response, then print its text. It has no memory, tools, private documents, or guarantee that the answer is true.

01

Your application

Collects the user’s question, selects a configured chat model, and decides how to display or validate the result.

02

Provider service

Authenticates the request with an API key, runs the selected hosted model, and applies its own availability and rate limits.

03

Returned message

Usually includes generated content and may include metadata such as usage or finish details. Treat metadata as provider-specific.

Prepare a small project

Use a virtual environment and keep secrets out of source control. The packages below are enough for this lesson; add integrations only when you use them.

Task: initialise a Python project and install LangChain with the Groq and Google integrations.

uv init first-chat-model
cd first-chat-model
uv add langchain langchain-groq langchain-google-genai python-dotenv

Create a .env file beside your script. Get a Groq key from the Groq quickstart, or a Gemini API key from the Gemini API key guide. Choose an available chat-capable model from that provider’s current model list; provider model identifiers change over time.

Task: store one provider key and its current model identifier outside the program source.

# .env — do not commit this file
GROQ_API_KEY=your_key_here
GROQ_MODEL=provider-current-chat-model

# Or use Google instead
GOOGLE_API_KEY=your_key_here
GOOGLE_MODEL=provider-current-chat-model

Make the first call with ChatGroq

LangChain gives chat integrations a similar invoke() entry point. It does not make all providers or models equivalent.

Task: ask the configured Groq model to explain HTTP and print the returned message.

import os
from dotenv import load_dotenv
from langchain_groq import ChatGroq

load_dotenv()

model = ChatGroq(model=os.environ["GROQ_MODEL"])
response = model.invoke("Explain HTTP to a beginner in three sentences.")
print(response.content)

For options, supported features, and current setup details, read the official LangChain ChatGroq integration guide.

THE SWITCHING RULE

Keep the application task stable; replace the model boundary.

In a real app, place construction of the configured model in one small function. The feature code can keep using model.invoke(message).

Task: select Groq or Google from one environment variable without changing the caller.

import os
from langchain_google_genai import ChatGoogleGenerativeAI
from langchain_groq import ChatGroq

def create_chat_model():
    provider = os.environ["CHAT_PROVIDER"]
    if provider == "groq":
        return ChatGroq(model=os.environ["GROQ_MODEL"])
    if provider == "google":
        return ChatGoogleGenerativeAI(model=os.environ["GOOGLE_MODEL"])
    raise ValueError("CHAT_PROVIDER must be 'groq' or 'google'")

reply = create_chat_model().invoke("Explain HTTP to a beginner in three sentences.")
print(reply.content)

The issue: a common call is not a common contract

Changing the constructor is often straightforward. Choosing a provider still changes the system you are operating.

Identifiers

Each provider names models differently. Use its current catalog; do not infer a model name from another provider.

Features

Context size, multimodal input, tools, structured output, streaming, and option names can differ by model.

Credentials

Keys, project setup, regional access, and account requirements are provider-specific.

Limits & cost

Rate limits, quotas, latency, and billing change over time. Check official current terms before a production choice.

Output

Even with the same prompt, models may vary in quality, style, refusal behavior, metadata, and response shape.

TERMS TO KEEP SEPARATE

Deployment and licensing answer different questions.

Useful distinctions when choosing a model
TermWhat it describesWhat it does not guarantee
HostedA provider operates the model service for you.That the model is proprietary, low-cost, or available everywhere.
Self-hostedYou or your organisation operate inference infrastructure.That weights may be redistributed or changed.
ProprietaryThe weights or significant rights remain controlled by a provider.That the model can only be hosted by that provider in every arrangement.
Open-weightWeights are available under stated terms.An open-source licence, unrestricted use, or no operating cost.
Open-sourceCode and/or model components are released under an open-source licence.That every related dataset, weight, or service term is also open.

Then switch the environment variable and repeat. Do not compare only prose quality; record any setup, limit, or capability difference you encounter.
